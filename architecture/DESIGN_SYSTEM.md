# Design System

The design system is defined conceptually in Sprint 3. No CSS, visual tokens, component styling, templates, images, JavaScript, or brand asset files are authorized.

## Visual Doctrine

StrongAvatar.com must look like an institutional reference system for governed digital identity, not a cartoon avatar maker, gaming toy, generic AI SaaS template, crypto landing page, cheap affiliate website, or hype-heavy startup surface.

The visual system should communicate control, authority, trust, technical seriousness, and editorial clarity.

## Preferred Direction

- Dark institutional interface.
- Deep graphite and black-blue foundation.
- Electric blue or cyan identity-field accents.
- White, silver, and muted slate typography.
- Controlled grid systems.
- Reference-grade spacing.
- Strong editorial hierarchy.
- Dense but readable information surfaces.
- Minimal ornamentation.

## Prohibited Aesthetic Directions

- Childish neon chaos.
- Mascot-driven avatar-maker aesthetic.
- Toy-like character creator interface.
- Prompt marketplace styling.
- Overused generic AI gradients.
- Conversion-heavy affiliate layouts.
- Hype-heavy startup style.
- Decorative visuals that imply public product functionality before publishing exists.

## Future Design Responsibilities

The future design system must support doctrine reading, protocol explanation, source transparency, quality status, internal link clarity, buyer logic, and acquisition diligence.

Design must never imply that users can create an AI avatar on the site unless a future approved product explicitly authorizes that function.

## Current Constraint

This file is visual doctrine only. It does not authorize CSS, templates, components, images, public pages, or generated output.
