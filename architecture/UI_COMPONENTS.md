# UI Components

UI components are defined conceptually in Sprint 3. No component code, CSS, JavaScript, HTML templates, placeholder UI, or generated site files are authorized.

## Component Doctrine

Future components must serve governed explanation, source transparency, registry-driven publishing, internal navigation, quality status, and institutional readability.

Components must reinforce StrongAvatar.com as the reference layer for avatar strength, synthetic likeness governance, and digital identity trust. They must not imply generic avatar creation, entertainment customization, or affiliate conversion.

## Future Component Inventory

- Sovereign hero block: introduces StrongAvatar.com and the Avatar Strength Protocol with institutional restraint.
- Thesis block: states the core asset thesis and foundational line.
- Protocol dimension card: explains one dimension of avatar strength with governance signals.
- Avatar Strength Score module: future assessment surface for evaluating governed representation.
- Comparison table: contrasts governed representation with weak or ungoverned avatar patterns.
- Governance warning block: flags risk, misuse, unsupported claims, or prohibited directions.
- Source note: displays source status, citation context, and evidence limitations.
- Reference disclaimer: clarifies educational, governance, or analytical boundaries.
- Buyer logic strip: connects content to strategic buyer categories without becoming a sales page.
- Monetization product card: presents approved future products only after monetization is authorized.
- Glossary term card: defines controlled terminology without creating thin glossary pages.
- Internal link rail: guides users through approved reference architecture.
- Acquisition signal block: communicates non-distressed strategic posture without valuation claims.
- Quality / last-reviewed marker: shows review state, source status, and maintenance discipline.

## Component Control Rules

- Components may render only approved registry-backed content.
- Components must not create routes or public pages independently.
- Components must not contain unauthorized calls to action, affiliate links, scripts, or tracking.
- Components must support accessibility, readable hierarchy, and source transparency.
- Components must not make the asset look like a SaaS landing page or avatar generator.
